# More operating systems, with commands that match

Today the wizard only offers Ubuntu 22.04, Ubuntu 24.04 and Debian 12, and every command is written the Ubuntu way (`apt`). This adds the rest of the common server systems and makes the generated commands correct for whichever one is chosen.

## The new list

CloudLinux 9 is the default (first and pre-selected).

- CloudLinux 9, CloudLinux 8
- AlmaLinux 10, AlmaLinux 9
- Rocky Linux 10, Rocky Linux 9
- CentOS Stream 10, CentOS Stream 9
- Red Hat Enterprise Linux 10, Red Hat Enterprise Linux 9
- Ubuntu 24.04 LTS, Ubuntu 22.04 LTS
- Debian 13, Debian 12
- Windows Server 2025, Windows Server 2022

The picker groups them by family so the list stays readable on a phone.

## Commands adapt to the choice

Each install step, verification check and troubleshooting fix is written once in a neutral form and rendered for the chosen family:

- **Debian family** (Ubuntu, Debian): `apt update`, `apt install -y ...`
- **RHEL family** (CloudLinux, AlmaLinux, Rocky, CentOS, RHEL): `dnf -y update`, `dnf install -y ...`, EPEL enabled where a package needs it, and `firewall-cmd` instead of `ufw`
- **Windows Server**: PowerShell throughout — winget/MSI installers, `Start-Service`, `Invoke-RestMethod` for the API checks, `New-NetFirewallRule` for ports, and remote access via `ssh` or RDP

Downloads follow the same rule: Linux picks give a `.sh` script, Windows picks give a `.ps1` script, both still shown in full before anything is run.

## Where a stack doesn't support a system

Each stack already declares which systems it supports. When someone picks one outside that list, the wizard shows a clear, non-blocking notice on the server step and on the results page naming which systems that stack is tested on, rather than silently producing commands that won't work. Windows support is declared per stack: Ollama, Open WebUI and n8n get real PowerShell paths; the Linux-only stacks say so plainly.

## Shareable links

The permalink already carries the chosen system; the new values are added to its allowed list so old links keep working and new ones restore correctly.

## Technical notes

- `OperatingSystem` in `src/lib/types.ts` becomes the expanded union, plus an `OsFamily = "debian" | "rhel" | "windows"` type and a single `src/lib/os.ts` catalog (id, label, family, group) used by the picker, the permalink allow-list and the generator.
- Stack data keeps `requirements.os` but gains optional `windows` step/check overrides; steps gain a per-family command form. Neutral placeholders (`{{pkg_update}}`, `{{pkg_install ...}}`, `{{svc_enable ...}}`, `{{http_get url}}`, `{{firewall_open port}}`) are resolved in `src/lib/generate/template.ts` from the family.
- Script generation branches on family for shebang vs PowerShell header, comment syntax and error handling; the `# Generated by Agent Deploy` marker required by the Gist endpoint is preserved in both forms (`#` works in PowerShell too).
- `src/lib/permalink.ts` `OPERATING_SYSTEMS` and the defaults in `Wizard.tsx` and `guide.$stackId.tsx` move to the shared catalog default (CloudLinux 9).
- Vitest cases: each family renders the expected package/service/firewall commands, Windows emits a `.ps1` with the marker, unsupported-OS notice fires, permalinks round-trip every new value.

## Not included

Detecting the server's real operating system — the tool still never connects to it.
